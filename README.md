# ai-manju-pipeline · AI 漫剧 / 同人 MV 生产流程

> 一套把「写剧本 → 出片」变成可重复执行流程的 AI 漫剧 / AI 短剧 / 二次元同人 MV 工作手册。
> 不是教程合集，是**能直接照着跑的生产 SOP**：14 份流程文档 + 7 个可运行脚本 + 1 个完整示例项目 + 一份路线图。

## 漫剧路线锁定（先看这条，不然整个流程你都用错了）

**漫剧走的是「Seedance 2.5 视频直出」路线：**

按分镜一次性生成 10–30 秒、**自带对白和可见口型**的片段，再拼接成片。

**不走**老流程：~~逐镜生图 → 图生视频 → 独立配音 → 对上口型~~。

生图环节**没有消失**，它从「每镜一次」变成了「**一次性做对、重复用 20 集**」——
只做角色三视图、定妆图、场景空镜、道具图、音色样本这些**项目级资产**。

---

## 三条铁律

1. **生视频是第 6 步，不是第 1 步。** 前 5 步全在做约束。模型的"演技"只在约束铺满后才兑现。
2. **资产一次做对，重复用。** 角色三视图 / 音色样本 / 场景空镜属于项目级资产，不是每集重做。
3. **先出选择题，再出正文。** 任何创作环节先给 5–6 个方向候选，选定再展开，别一上来写整本剧本。

## 8 阶段流程（漫剧）

```
① 立项选题          → 立项卡
② 剧本 + 分镜表      → 剧集大纲 / 剧本 / 分镜表          【停止点：剧情确认】
③ 资产层（生图）     → 角色圣经 + 素材编号表 + 参考图      【停止点：脸确认】
④ 音色层             → 音色参考台本 + 音色样本
⑤ 提示词层           → Seedance 2.5 提示词包（含上传清单）
⑥ 视频生成（你跑）    → 分镜片段 + 生成日志
⑦ 局部编辑与校准     → 改片指令包
⑧ 剪辑收尾 + 发布    → 收尾清单 + 发布物料               【停止点：成片确认】
```

**六件套交付物**：角色圣经 · 分镜表 · 提示词包 · 参考图 · 抽卡 SOP · 收尾清单。

## 怎么用

### 方式 A：当成 skill 装（推荐）

本仓库是一个标准 skill 目录包（`SKILL.md` + frontmatter）。放进你的项目里：

```bash
# Claude Code
cp -r ai-manju-pipeline  <你的项目>/.claude/skills/ai-manju

# DeepSeek Harness
cp -r ai-manju-pipeline  <你的项目>/.dsh/skills/ai-manju
```

之后提到「做漫剧 / 短剧剧本 / 分镜表 / Seedance 提示词 / 角色三视图 / 同人 MV / 拼贴风」就会自动触发。

### 方式 B：只想用脚本

```bash
# 0. 建项目骨架（漫剧 / 同人 MV）
python scripts/init_project.py --type manju --name 她的第二次人生
python scripts/init_project.py --type mv --name 夏日信笺 --role 角色A

# 1. 分镜表 → Seedance 2.5 提示词包（两层编号换算 + 上传清单 + 15 类体检）
python scripts/build_prompts.py \
  --shots  <项目>/01_剧本/第01集_分镜表.csv \
  --assets <项目>/02_资产/_素材编号表.csv \
  --out    第01集_提示词包.md \
  --title  "她的第二次人生 · 第01集"

# 2. 跨集一致性检查（做到第 5 集就该跑）
python scripts/check_consistency.py --project <项目目录>

# 3. 同人 MV 分镜表体检 / 导出字幕 / 抽卡复盘
python scripts/check_mv_shots.py --shots <项目>/01_脚本/01_MV分镜表.csv
python scripts/make_srt.py --shots <分镜表.csv> --out 字幕.srt
python scripts/log_summary.py --log <项目>/生成日志.csv
```

### 方式 C：只想读文档

直接看 `references/`。`01` → `06` 是漫剧主流程，`07` 是速查，`08`–`11` 是按需读的支线，`12`–`14` 是同人 MV 路线。

## 脚本

| 脚本 | 干什么 |
|---|---|
| `build_prompts.py` | 分镜表 + 编号表 → Seedance 2.5 四段式提示词包 |
| `check_consistency.py` | 跨集一致性检查 |
| `check_mv_shots.py` | MV 分镜表体检 + 镜头类型 / 段落节奏统计 |
| `make_srt.py` | 分镜表 → SRT 字幕（漫剧台词 / MV 歌词，支持双语） |
| `log_summary.py` | 生成日志汇总：抽卡率、废片原因、工时、花费 |
| `init_project.py` | 一键建项目骨架 |
| `run_selftest.py` | 全部脚本回归测试 |

### `build_prompts.py` —— 分镜表 → 提示词包

**两层编号**：编号表里的 `图片6` 是全局资产 ID；即梦里的 `@图片1` 是**这一次上传的第 1 张图**。
脚本把编号表编号换算成每条生成的上传槽位，按 **图片 → 视频 → 音频** 排好，并在每条上方输出上传清单：

```
| 顺序 | 提示词里写 | 编号表 | 主体 | 文件 |
| 1 | @图片1 | 图片1 | 林晚 | 林晚_三视图_v1.png |
| 2 | @图片2 | 图片6 | 婚礼彩排晚宴厅 | 婚礼彩排厅_空镜_v1.png |
| 6 | @音频1 | 音频2 | 苏黎 | 苏黎_音色参考_10s.wav |
```

**自动做的事**
- 按 `段号` 归组；遇到 `合并到` 列就把相邻段合成**一条生成**，时间戳**自动累加偏移**，每段的概述和守则都保留
- 从编号表取「用途 / 不采用」生成素材指代句（音频自动换「作为…」句式）
- 逐段拼时间戳行：`景别/运镜 → 画面内容 → 动作细节 → 说话人说{台词} → <音效>`
- 输出末尾附「本集素材清单 + 校验报告 + 生成后必做清单」

**校验报告会揪出 15 类毛病**
① 段内时间戳重叠　② 台词字数超区间　③ 合并后总时长超 30 秒　④ 单段超 12 秒
⑤ 素材编号查不到　⑥ 说话人写成「角色1 / 人物2」这类占位名　⑦ 整条没有参考素材
⑧ 参考图超 8 张　⑨ 视频/音频素材超上限　⑩ 时间区间格式写错　⑪ 段时长写法解析不了
⑫ **有台词的说话人没挂自己的音色**　⑬ 台词没写说话人　⑭ 一条生成混了两种语言　⑮ 提示词超过 1500 字

参数：`--ratio`（守则自动写竖屏 / 横屏）、`--res`、`--cps`（台词语速，真人风调到 4–4.5）。

### `check_consistency.py` —— 跨集一致性检查

单集做没问题，做到第 8 集就会发现：角色脸换了、素材编号重编了、说话人写成「角色2」、上一集结尾受了伤下一集开头伤没了。**这些漂移单看每一集都看不出来。**

自动查找项目里的 `*素材编号表*.csv`、`*分镜表*.csv`、`*剧情状态表*.csv`。

**报错**：引用不存在的编号 / 说话人占位名 / 台词超时长 / 时间戳重叠 / 同一编号指向两个主体
**警告**：段号不连续 / 整段无参考素材 / 同主体同类型有多个资产（换脸风险）/ 角色有台词但没音色或这条没挂音色 / 剧情状态跨集接不上
**提示**：孤儿资产 / 编号表登记但文件不存在 / 命名不规范 / 系列圣经锚点清单

**退出码 0 = 无错误，1 = 有错误**，可以放进发布前的自动检查。

## 适用范围与边界

**这套流程能覆盖的**：① 立项 ② 剧本分镜 ③ 资产 ④ 音色 ⑤ 提示词 ⑦ 局部编辑；⑧ 的清单、工程规范、字幕导出。

**这套流程覆盖不了的**（文档里给清单和 SOP，实际得你自己操作）：
- ⑥ **视频生成** —— 要你自己在即梦 / 豆包 / 火山方舟或本地 ComfyUI 跑，本文档给的是提示词和抽卡策略
- **音色样本录制/合成**
- **剪辑操作**（剪映 / PR / AE）

## 关于具体模型型号

文档里出现的模型名（Seedance 2.5 / Seedream 5.0 Pro / GPT Image 2.5 / Nano Banana Pro / Z-Image / Anima / Qwen-Image 2.1 / MiniMax H3 等）
是写作时（2026-10）的版本。**AI 视频和图像模型迭代很快，选型表会过期，但流程结构不会。**

选型表和许可证表在 `references/07-翻车点与模型选型.md`，用之前先对一下最新官方文档；**做商业项目前逐个核对模型许可**。
