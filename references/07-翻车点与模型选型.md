## 一、翻车点总表（症状 → 原因 → 修法）

### 角色一致性

| 症状 | 原因 | 修法 |
|---|---|---|
| 跨集角色变脸 | 只喂了文字，没喂参考图 | 挂三视图；一图一视角；别拼图 |
| 同一条里中途变脸 | 段太长（>12 秒） | 缩短段长；加强结尾守则 |
| 脸是主角但气质不对 | 表情/状态图没挂 | 补挂对应状态图 |
| 换了服装 | 服装没写进素材指代 | 补服装参考图，或改定点编辑 |
| 画面里冒出不认识的人 | 素材里带了背景人物 | 素材写"不采用图片背景"；守则写"只有这 N 人" |

### 音画同步

| 症状 | 原因 | 修法 |
|---|---|---|
| 音画不同步 | 没打时间戳 | 逐句打 `3s-6s`；区间不重叠；单句 +0.5 秒缓冲 |
| 口型全乱 | 时间戳重叠 | 检查所有区间无交叠 |
| 全片系统默认音 | 音色绑定失败 | 上传顺序（音色第 4 位）；勾「仅当前角色可用」 |
| 音色串用 | 多角色未逐个绑定 | 每角色单独绑 |
| 部分句子没声音 | 该句时间戳太短 | 字数 ÷ 5 + 0.5 秒 |
| 台词说出了奇怪语言 | 一条里混两种语言 | 每次生成只用一种 |
| 台词被改字 | 正常波动 | 剪辑时用字幕兜底；关键台词重抽 |

### 画面

| 症状 | 原因 | 修法 |
|---|---|---|
| 片尾莫名出现字幕 / BGM | 没写否定约束 | 提示词写「不要字幕」「不要背景音乐」 |
| 画面里画出了文字 | 用了 `【】` 或写了"标题" | 去掉；字幕交给剪映 |
| 多主体画面乱 | 素材超稳定区 | 主体图收到 8 个以内，分场景派活 |
| 动作崩坏 | 写了狂奔 / 大跳 / 翻滚 | 避开高爆发动作；能量交给剪辑和运镜 |
| 画面"油腻" | 用了 2.0 的老问题 | 用 2.5（专门优化过材质、肤质、光影、饱和度） |
| 光影段间跳 | 每条 prompt 的光影句不一致 | 统一从系列圣经抄 |
| 色调不统一 | 没写色调三层结构 | 主/次/点缀色写全 |
| 复杂运动物理不合理 | 官方承认的模型短板 | 拆分动作；用定点编辑补 |
| 极多主体交互不稳 | 官方承认的模型短板 | 超过 3 人就拆段 |

### 流程

| 症状 | 原因 | 修法 |
|---|---|---|
| 提示词对不上素材 | 每段重新从 `@图片1` 编号 | 用全局素材编号表 |
| 20 集后素材找不到 | 没建目录规范 | 见 `assets/项目目录与命名规范.md` |
| 抽卡次数爆炸 | 一上来就跑完整集 | 先跑 seg01 校准 |
| 改一集要重做资产 | 资产没做成系列级 | 三视图/音色一次做对，全集复用 |

## 二、Seedance 2.5 vs 2.0（什么时候用哪个）

| 能力 | 2.5 | 2.0 |
|---|---|---|
| 单次时长 | **30 秒** | 15 秒 |
| 参考素材 | **50 份**（图 ≤30 / 视频 ≤10 / 音频 ≤10） | 15 份 |
| **秒级时间戳** | ✅ 一等公民 | ⚠️ 官方明确"对精确时间支持不稳定、不建议强卡" |
| 原生对白 + 可见口型 | ✅ | 部分 |
| 多语言 | 10+ 语言 | 较少 |
| 画幅 | **0.4–2.5 任意比例** | 固定 6 档 |
| 新增能力 | 白模渲染 / **宫格分镜** / 绿幕编辑 / 视角运镜编辑 / 无缝转场 / 局部定点编辑 / 首尾帧 / 纯音频驱动 | — |
| 价格 | **¥70 / 百万 token** | ¥46 |
| 官方承认短板 | 复杂运动物理合理性、极多主体交互稳定性 | 更多 |

**结论**：重头戏（有台词、关键情绪、开场结尾）用 2.5；过场、空镜、无人段用 2.0 省钱。**2.5 比 2.0 贵 52%，但不是所有镜头都值这个钱。**

**稳定区（别贪上限）**：

| 类型 | 上限 | 推荐稳定区 |
|---|---|---|
| 图片 | 30 张（单张 ≤4K） | **1–8 个主体**（可扩到 9–12） |
| 视频 | 10 段（总 ≤30 秒） | 1–5 个主体，单段 5–10 秒 |
| 音频 | 10 段（单段 2–30 秒、≤15MB、总 ≤30 秒） | 只留与任务直接相关的 |

*（部分站点标 2.5 最长可到 50 秒，非官方口径，别依赖。）*

## 三、模型选型总表（2026-10）

| 环节 | 首选 | 备选 | 为什么 |
|---|---|---|---|
| **剧本 / 分镜 / 提示词** | DeepSeek V4 · 豆包 | Claude · GPT | 中文短剧节奏、爽点密度强 |
| **生图（三视图 / 场景 / 道具）** | **Seedream 5.0 Pro**（即梦） | 即梦 4.x · Lib Nawo 2 | 与 Seedance 2.5 同厂同平台，资产直接复用；区域编辑强；主体保持好；原生 4K；中文渲染强 |
| **写实兜底 / 图内文字 / 多参考图** | **Nano Banana Pro**（Google） | Nano Banana 2 · GPT Image | 人物 ID 零样本锁定；图内文字准确率 94–96%；支持 >10 张参考图；4K |
| **生视频（核心）** | **Seedance 2.5** | Seedance 2.0（省一半钱）· 可灵 | 30 秒直出；50 份参考；原生对白 + 可见口型；秒级时间戳；音色复刻 |
| **音色参考 / 配音素材** | 豆包语音 · 剪映朗读 | 真人自录 · Seed Audio 1.0 | 生成 5–15 秒干净音色样本 |
| **剪辑 / 字幕 / 音效** | 剪映 | CapCut · PR | 智能字幕 + 音效库 + 便宜 |
| **封面** | Seedream 5.0 Pro | Nano Banana Pro | 中文标题字渲染 |

### 一句话结论

> **主力一条龙走字节系：DeepSeek/豆包写 → 即梦 Seedream 5.0 Pro 出图 → 即梦 Seedance 2.5 出视频 → 剪映收尾。**
> 三个理由：① 账号资产打通，参考图不用导来导去；② 中文提示词和中文文字渲染最强；③ 全中文界面，出问题好排查。
>
> **Nano Banana Pro 当"特效药"**：写实质感不够、要往图里排中文字、参考图超过 10 张、要 4K 时用它。

### 选型分界线（记这两条）

- 要 **4K / 参考图 >10 张 / 画面依据实时信息** → **Nano Banana Pro**
- 要 **框选、箭头、坐标定点改** / 要 **带透明通道的分层 PNG** → **Seedream 5.0 Pro**

## 四、附录：本地免费出图路线（ComfyUI + Z-Image）

资产量大时，本地出图能省掉大部分生图开销。

| 项 | 情况 |
|---|---|
| 模型 | Z-Image-Turbo（阿里开源，6B，蒸馏版） |
| 权重 | INT8 三件套约 11.3GiB |
| 官方参数 | **steps 8 · cfg 1.0**（Turbo 是蒸馏模型，cfg>1 会糊）· clip type 选 `lumina2`（**不能选错**） |
| VAE | `ae.safetensors` 是 **Flux 系 16 通道 VAE** —— 拿 Qwen/Wan 的 VAE 顶替会偏色 |
| 放大修复 | 出图 → `UpscaleModelLoader`（4x-UltraSharp / 4xFaceUpDAT）→ `ImageScaleBy` → 第二次低 denoise KSampler 补细节 |
| 8GB 显存坑 | 爆显存 → `ImageScaleBy` 降到 0.25 或出图降到 912×512 |
| 过锐发脆 | denoise 降回 0.2，或放大模型换回 4x-UltraSharp |
| ControlNet | `Z-Image-Turbo-Fun-Controlnet-Union-2.1-lite-2602-8steps.safetensors` 放 `models\model_patches\`，节点下拉框手动选 |

**本工作区已有**：`Z-Image_工作流清单.md`、`zimage_setup.py`、`install_zimage.bat`、`download_anima.ps1`

**建议分工**：
- 本地 Z-Image → 出**草稿、表情包、大量变体试错**
- 云端 Seedream 5.0 Pro → 出**定稿三视图、定妆、封面**（白底更干净、主体保持更稳）
